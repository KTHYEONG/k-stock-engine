# 백테스트 데이터 준비 현황과 수집 계획

기준일: 2026-09-20. 수치는 현재 `data/bronze/stocks` 원본과 수집 계획·완료 기록을 직접 집계했다. DART 잔여 수집 후 재측정한다. 전략과 백테스트 규칙은 [strategy.md](strategy.md)에 둔다.

## 산업 업종: 원천과 저장

**1순위 원천은 KRX Data Marketplace의 `업종분류 현황`**이다. KRX 공식 메뉴에 이 자료가 있으며 [상장폐지종목 현황](https://data.krx.co.kr/contents/MDC/STAT/issue/MDCSTAT238.jsp)에도 폐지 직전 업종명이 표시된다([KRX 데이터 메뉴](https://data.krx.co.kr/contents/MDC/MAIN/main/index.cmd?locale=en.)). 현재 KRX OpenAPI 종목 마스터 원본에는 산업 업종이 없다. Data Marketplace의 과거 날짜 조회·자동 내려받기 조건은 아직 검증되지 않았다. 공개 화면 호출의 2016년/2026년 소규모 시험은 이 환경에서 오류 페이지를 반환했다. 따라서 과거 업종을 지금 종목명으로 소급 채우는 작업은 금지한다.

| 단계 | 계약 |
| --- | --- |
| 공급처 실증 | KRX 공식 화면 또는 승인된 API에서 KOSPI·KOSDAQ의 과거 기준일 두세 개와 최근 기준일을 내려받아 종목코드·업종명·기준일·폐지 종목 포함 여부를 확인한다. 성공하지 않으면 산업 업종은 미수집 상태로 둔다. |
| 원본 보관 | 시장·요청 기준일·수신시각·공급처·원본 파일 해시·응답 상태를 적은 receipt와 원본 바이트를 `data/bronze/stocks/industry_classification/`에 불변 보관한다. 같은 내용의 중복 수신은 해시로 합친다. |
| 정규화 | 관측 키를 `(as_of, market, instrument_id, source_hash)`로 두고 `classification_system`, 업종명, 제공될 경우에만 업종코드, `available_at`, `retrieved_at`, `evidence_status`를 기록한다. 변경 유효일이 확인되지 않으면 스냅샷 사이의 모든 날짜에 같은 업종이었다고 추정하지 않는다. 종목코드 재사용은 ISIN/시점별 마스터로 분리한다. 소속부 `SECT_TP_NM`은 산업 업종 필드에 절대 대입하지 않는다. |
| 효율 | 과거 백테스트가 월별 판단이면 우선 리밸런싱 직전일의 양 시장 스냅샷만 확보한다. 매일의 업종 변화를 주장해야 할 때만 일별 수집한다. 실거래는 새 분류 변경을 놓치지 않도록 정기 스냅샷과 변경 감시를 운영한다. |
| 대안 | KRX의 역사 자료가 불가하면 검증된 이력 제공처를 새 원천으로 평가한다. 현재 자료만 있는 업종이나 공시의 사업 설명문으로 2016년 업종을 추정하지 않는다. |

## 투자자 수급: 미백필과 원천 한계 분리

**판정: 전체 시장 수집 불가능으로 볼 근거는 없다. 주된 문제는 백필 미완료이며 일부 종목·날짜는 공급처 오류로 남아 있다.**

- 기존 2016년 LS 계획은 2,129종목 중 1,774종목에 완료 기록이 있다. 그 계획의 미완료 355건에 해당하는 LS 음성 응답은 `source_unavailable` 315건과 `provider_error` 40건이다. 별도 Kiwoom 경로에도 2016년 요청을 가리키는 `source_unavailable` 2,026건이 있어 공급처·요청 형식·응답 범위를 다시 검증해야 한다. `source_unavailable`은 요청 거래일이 응답에 없다는 로컬 판정도 포함하므로 영구 미지원 증거가 아니다.
- 2017~2025년 전 시장을 대상으로 한 완료 계획은 보이지 않는다. LS 원본에는 일부 약 143종목의 3개년 묶음 응답이 있으며 한 요청에서 700거래일 이상이 실제 반환됐다.
- 아직 저장되지 않은 `000850`의 **2018년**을 LS `t1702`에 단일 조회한 결과, 244거래일 응답이 반환됐다. 따라서 `2018년 143종목`은 원천의 전 시장 한도로 해석할 수 없다. 이 확인 조회는 Bronze에 저장하지 않았으므로 백필 완료 수에 포함하지 않는다.
- 2026-03~09 계획은 표기상 3,080종목이지만 실제 각 종목의 세션은 최근 5일뿐이고 완료 기록은 0개다. [collection_plan.py](../../src/data/collection_plan.py)의 원본 계획 로직은 역사 마스터의 `receipt.retrieved_at`이 대상 거래일보다 늦으면 그 마스터를 버린다. 2026년에 재조회한 과거 기준일 자료가 과거 백필 계획에서 빠지는 직접 원인이다.
- 현재 CLI의 수동 `--sessions` 경로는 입력 종목을 모두 `is_common_stock=True`로 선언한다. 이 경로도 원본 종목 마스터 검증을 통과시키거나 운영 수집에서 차단해야 우선주 완전 제외가 지켜진다.

### 백필 실행 설계

1. 날짜가 명시된 KRX 과거 마스터의 **기준일**로 당시 일반 기업 보통주와 거래일을 구성한다. 수집한 날을 상장 유효일로 쓰지 않는다. 기준일이 없는 이관 응답은 단독으로 과거 집합을 증명하지 못한다.
2. `종목 × 연속 거래일 묶음`으로 미수집 구간만 계획한다. LS는 기존 성공 사례에 맞춰 최대 700거래일 묶음으로 시작하고 실제 응답 길이·시작/끝·누락을 검증한다. 빈 응답, 서버 오류, 요청일 일부 누락을 서로 다른 상태로 기록한다.
3. 기존 2016년 완료 건과 원본 해시를 재사용한다. 역사적으로 상장하지 않았거나 당시 우선주였던 종목에는 요청하지 않는다. 2017~2025년을 연도별·시장별로 진행하며 API 속도와 일일 제한을 설정으로 관리한다.
4. LS 실패분은 일시 오류 재시도 후 Kiwoom/KIS의 사용 가능 범위를 소수 종목·날짜로 비교한다. 공급처별 매수·매도·순매수의 단위와 부호를 일치 확인한 뒤 교차 공급처를 채택한다. KRX 공식 [개별종목 투자자 거래실적](https://data.krx.co.kr/contents/MDC/MAIN/main/index.cmd?locale=en.)도 대체 원천 후보이나 자동 이력 접근과 이용 조건을 먼저 검증한다.
5. 매 수집 단계마다 예상 일반 보통주×거래일 대비 실제 `유효/공급처 미지원/일시 오류/미요청` 수를 보고한다. 미응답을 0 순매수로 바꾸지 않는다. 재무·가격과 결합할 때 공급처·수신시각·원본 해시를 보존한다.

## 완료 판정

백테스트 입력 확정 전 다음을 날짜·종목 단위로 출력한다: 일반 보통주 분류의 미확인 수, 거래 가능 일봉 비율, 업종 분류 유효 비율, 수급 공급처별 커버리지, 재무 필수 항목 PIT 커버리지, 미해결 기업행위·상장폐지 노출, 비용 범위. 실패 항목은 전략 점수로 보정하지 않고 해당 거래 또는 평가 기간의 인증을 막는다.

과거 파생 데이터와 임시 파일의 보존·제거 순서는 [data_cleanup.md](data_cleanup.md)에 기록했다. 수급 수집 계약은 [investor_flow_backfill_spec.md](../specs/investor_flow_backfill_spec.md)에 정의했다.
